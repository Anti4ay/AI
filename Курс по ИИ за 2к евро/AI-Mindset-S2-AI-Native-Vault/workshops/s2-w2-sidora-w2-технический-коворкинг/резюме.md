# W2: Технический коворкинг

[![W2: Технический коворкинг](https://img.youtube.com/vi/bXNJiwR_ff4/maxresdefault.jpg)](https://youtube.com/watch?v=bXNJiwR_ff4)

## Summary
Технический коворкинг в формате Q&A с **Глебом Сидорой** — co-founder Codos, ex-Meta. Глеб разворачивал первые LLM в Facebook, затем со-основал Codos с **Димой Ханариным** (ex-McKinsey). Идея Codos: Дима делает консалтинг, Глеб автоматизирует его — система постепенно берёт на себя всё больше консалтинговых задач. Ядро системы — управление базой знаний: чтобы агенты работали хорошо, им нужен правильный контекст.

**Формат сессии:** не лекция, а открытые вопросы-ответы. Участники заранее готовили вопросы по теме пятничного доклада Глеба о графах знаний.

**Хранение знаний.** Главный лернинг Глеба за полгода: файловая система работает лучше всего. Markdown-файлы с перекрёстными ссылками (zettelkasten-подобный подход) масштабируются до компаний в 500-1000 человек. Графовые базы (Neo4j) «рассыпались даже с небольшим количеством документов». У Codos порядка 10 тысяч файлов — всё работает быстро и надёжно. MCP-сервисы работают плохо с большим объёмом данных из-за latency — все данные лучше хранить локально.

**AI-трансформация организаций.** Глеб описал уровни зрелости: (0) никто не использует AI → (1) каждый использует хоть как-то → (2) персональные AI-сетапы → (3) корпоративная база знаний → (4) реструктуризация организации → (5) always-on агенты. Метрика зрелости — отношение always-on агентов к людям. У Codos: 10 агентов на 3 человека (3.3).

**Ключевые дискуссии:**
- **MCP как стандарт:** Стас Федосеев высказал сомнение («не очень удачный стандарт, скоро отомрёт»), Глеб аргументировал текущую полезность, но отметил проблемы с latency
- **Prompt injection:** обсуждение рисков в корпоративном контексте — Глеб рассказал, как Codos разделяет агента с полным контекстом (пишет скрипт интервью) и агента-интервьюера (имеет только скрипт, безопасный для эксфильтрации)
- **Детерминистические скрипты внутри агентов:** «скрипт никогда не забудет, агент забудет каждый пятый раз» — маленькие скрипты для валидации ссылок, триггеров обновлений и проверки консистентности
- **Ваншот vs итеративная разработка:** Anthropic делает браузер с нуля одним промптом, но развивать существующий продукт «сюрпрайзингли сложнее, чем заваншотить новый»

## Homework
- [ ] **A1 (базовый):** Создайте папку с 10-15 markdown-файлами по вашему проекту (база знаний, заметки, документация). Добавьте CLAUDE.md с оглавлением. Попробуйте работать с Claude Code поверх этой папки — оцените качество ответов (~30 мин)
- [ ] **A2 (средний):** Постройте систему перекрёстных ссылок между файлами: добавьте ссылки на связанные документы, сделайте иерархию папок с CLAUDE.md в каждой. Напишите простой скрипт валидации ссылок (~1-2 ч)
- [ ] **A3 (продвинутый):** Реализуйте пайплайн обработки новых данных: загрузка транскрипта → саммаризация → обновление связанных файлов через детерминистический скрипт + субагентов. Сравните результат с подходом «всё в одном агенте» (~3-4 ч)
