# W2: Сессия кураторов

## Summary
Сессия трёх кураторов AI Mindset, каждый из которых раскрыл свой слой AI-native архитектуры из лекции Степана Гершуни.

**Джин Колесников** (20 мин) — «Почему AI-чемпионов недостаточно». По данным BCG, 85% сотрудников застревают на стадиях «наблюдатель» или «адаптер», менее 10% доходят до полуавтономного использования AI. Проблема не в людях, а в среде. Джин разобрал кейсы Shopify (практика встроена в культуру), Citi (доверие через отношения), Haier (4000 микропредприятий вместо чемпионов) и предложил 5 элементов среды: конкретные роли роста, доступ к лучшим моделям, пространство для легитимной практики, признание и карьерный рост, доверие через примеры коллег. Отдельно затронул тему AI-выгорания — мониторинг здоровья, помидоро-паузы, полное отключение на час в день.

**Денис Смирнов** (25 мин) — «Как превратить данные в рабочий контекст для агентов». Ключевой тезис: наличие данных ≠ контекст. Контекст появляется, когда определены сущности, связи и временные метки. Три режима доступа: ручной экспорт (быстро, но статично), официальные API (живые пайплайны), кастомная интеграция (вебхуки для реального времени). Разобрал конкретику по Gmail, Notion, Telegram (Telethon vs Bot API). Важное наблюдение: даже модели с 1M токенов показывают «слепоту» в центре контекста — лучше разбивать на тематические сущности. Домашнее задание: вручную извлечь данные из своих систем, задокументировать ошибки и ограничения.

**Станислав Глазов** (30 мин) — «Процедурный подход к агентным пайплайнам». 25 лет в процедурных системах, сейчас 17 проектов на одного человека с 1300+ коммитов в месяц. Философия: каждый скилл может органически вырасти через 5 логических гейтов — от промпта к скиллу, от скилла к CLI-утилите, от утилиты к микросервису. CLI-first подход: утилиты потребляют 0 токенов (в отличие от MCP), работают надёжно после настройки. Показал свои инструменты: H-Toothy Vision (computer vision для агентов), H-Toothy Snap (17MB — агент видит экран и кликает), Whisper Pipeline с промптами для качества транскрипции. Medallion-архитектура данных: Bronze (сырые) → Silver (нормализованные, дедупликация, связи через LLM) → Gold (чистые для Obsidian и агентов). Анонсировал платформу SpecDesigner — «MVC для агентов».

**Ключевой вывод:** три куратора показали три уровня зрелости AI-интеграции — от организационной среды (мотивация и культура) через инфраструктуру данных (контекст из хаоса) до продвинутых процедурных систем (CLI-first, self-improving pipelines). Каждый уровень необходим для полноценной AI-native организации.

## Tools
- [[Claude Code]] — Основная агентская среда для всех трёх кураторов
- [[Obsidian]] — Хранилище очищенных данных (Gold layer)
- [[Telethon]] — Python-библиотека для прямого доступа к Telegram
- [[Whisper]] — OpenAI транскрипция с промптами для качества
- [[H-Toothy Vision]] — Computer vision для сегментации экрана агентом
- [[H-Toothy Snap]] — 17MB утилита: агент видит экран, кликает, печатает
- [[jq]] — CLI-инструмент для валидации JSON/structured data
- [[NetworkX]] — Методология для построения контекстных графов

## Homework
- [ ] **A1 (базовый):** Возьмите 2 источника данных (один простой — Gmail/Trello, один сложный — Telegram/Discord). Ответьте на 5 вопросов: откуда берёте данные, в каком формате, что является единицей контента, можно ли обойтись без кода, где нужна прослойка. Сохраните ошибки и скриншоты (~1 ч)
- [ ] **A2 (средний):** Выгрузите данные из 2-3 своих сервисов (почта, мессенджер, таск-менеджер). Определите для каждого: сущности, связи, временные метки. Нормализуйте в единый формат (markdown или JSON). Не засовывайте в агента — сначала разберитесь в структуре (~2-3 ч)
- [ ] **A3 (продвинутый):** Постройте ETL-пайплайн для одного источника: экстракт → нормализация → enrichment через LLM → валидация через jq → загрузка в Obsidian/базу данных. Реализуйте как CLI-утилиту, доступную из любого репозитория (~4-6 ч)
