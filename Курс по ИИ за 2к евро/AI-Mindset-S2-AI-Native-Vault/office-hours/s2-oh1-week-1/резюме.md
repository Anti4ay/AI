## Summary
Первые Office Hours второго сезона AI-Native Organizations Sprint. Формат вопрос-ответ, где участники задавали практические вопросы о работе с AI-агентами, организации рабочих процессов и стратегии трансформации бизнеса. Степан Гершуни показывал живые демо своих инструментов.

### Исправление багов и итеративная разработка

Михаил поднял проблему, знакомую многим вайбкодерам: создание приложения занимает 10% времени, а исправление багов — 90%. Обсудили подходы:

- **Итеративность**: планирование и реализация — разные фазы. Тестирование отдельно.
- **Реверс-инжиниринг ошибок**: сломалось — найди причину — зафиксируй как документ — сделай заново лучше.
- **OpenSpec**: протокол спецификаций для структурирования задач через документацию.
- **Полный рефакторинг**: иногда проще сказать Клоду «напиши всё, что есть функционально, удали код и переделай с нуля». Это нормальная практика.
- **Сохранение требований**: всегда фиксировать образ результата (CRD/BRD), чтобы при рефакторинге не начинать с нуля.
- **Output style**: настройка интенсивности мышления модели в Claude Code.

### Переход от роутера к оркестратору

Алексей описал ситуацию: параллельно работают 4-5 агентов в Cursor и Claude, а он выступает «роутером» между ними. Как перейти на следующий уровень?

- **Ожидание идеального результата** — психологический баяс при работе с AI. Реальность всегда посередине.
- **Оркестратор строится итеративно**: версия 1 ужасна, потом тюнинг каждого элемента.
- **Всё меняется быстро**: через 3 месяца оркестраторы будут выглядеть совершенно иначе.
- **Ментальная модель**: «Мы не строим системы, мы их открываем» — как физику, возможности LLM открываются эволюционно.
- **Фиксация абстракций**: можно зафиксировать отдельную функцию (дизайнер, креатив) как скилл на несколько месяцев и не трогать.

### Скиллы, скрипты и агенты: как организовать зоопарк

Никита спросил о разграничении между скиллами, хуками, агентами и скриптами. Степан показал демо своей системы:

- **Ежедневный бриф**: команда `/brief` запускает чтение Telegram, Gmail, календаря.
- **Скилл для Telegram**: как получать, читать, сохранять сообщения, писать драфты.
- **Workflow для интродакшенов**: автоматизация создания Telegram-групп для знакомств (частая задача в инвестициях).
- **Хранение**: всё лежит в файлах — звонки, имейлы, Telegram-сообщения — в папке context.
- **Индексация сущностей**: SQLite база данных с named entity recognition через Haiku — компании, люди, количество интеракций.
- **Четыре типа извлечённых данных**: решения, action items, промисы (кто кому что обещал), инвестиционные сделки.
- **Confidence score**: каждая извлечённая сущность имеет оценку уверенности и прямую цитату из источника.

### Мультиагентность: субагенты vs настоящие агенты

Алексей задал фундаментальный вопрос о двух типах агентов:

1. **Субагенты** — промт внутри одной сессии, нет своего CLAUDE.md, просто инструкция поведения.
2. **Настоящие агенты** — отдельная сессия Claude Code, свои инструменты, свой контекст, свои MCP-серверы.

Степан объяснил:

- Для **персональных задач** мультиагентность почти не нужна, кроме параллельной разработки через Git worktrees.
- Субагент — это тот же чат с теми же инструментами, но с пустым окном контекста.
- **Зеркальные агенты**: у маркетолога и продакт-менеджера свои агенты, которые могут общаться между собой и находить пересечения.
- **Разделение по правам доступа**: корпоративный агент с доступом ко всей базе клиентов, но без доступа к интернету.
- **Agent SDK**: переходить когда есть команда для поддержки, потому что Claude Code выпускает 3+ релиза в неделю, и SDK постоянно ломается.
- Файловая система — самое простое решение для оркестрации: запуск агента = текстовый файл с инструкциями, результат = текстовый файл с артефактами.

### Память агентов и самоулучшение

Иван поднял три связанных вопроса:

1. **Авторефлексия**: как автоматизировать, чтобы агент сам сохранял полезные навыки?
   - Использовать **hooks** — скрипт, который выполняется в конце сессии (session end hook).
   - Не делать самоулучшение ежедневно — лучше смотреть статистически за неделю/месяц.

2. **Структура памяти**: Антропик рекомендует максимум 3 слоя глубины (CLAUDE.md → файл → файл).
   - Выносить глубокие структуры в отдельные скиллы.
   - Для 100% надёжности — использовать базу данных вместо файлов.

3. **Синхронизация между локальным окружением и VM**: Git, Obsidian Sync, Google Drive, Box (с API и MCP).

### Автоматизация по расписанию

Михаил спросил, как запускать агентов автоматически:
- **Codex**: встроенная вкладка Automations — выбрать проект, расписание, задачу.
- **Claude Code**: написать bash-скрипт с `claude -p "запусти мой ежедневный бриф"`, поставить в планировщик задач (Cron/LaunchD/Планировщик Windows).
- **Open Claw**: из коробки на VPS.

### Автоматизация инвестиционной деятельности

Настя спросила про knowledge extraction для венчурного фонда:
- **Индексация раз в сутки**: скрипт смотрит новые файлы в Git, парсит и складывает в базу.
- **Два уровня**: мониторинг рынка (поиск новых стартапов, фаундеров) + трекинг портфеля (отчёты, звонки, перформанс).
- **Пример USV**: статья о том, как USV автоматизировали свой фонд — агенты по ролям (аналитик, имейлы, финансы, календарь, legal).

### Перестройка инженерного отдела на AI

Александр спросил о командной разработке с AI:
- **Реальный кейс**: портфельная компания-брокер сократила команду разработки в 2 раза и сделала годовой план за 3 месяца.
- **Вайбкодеры не заменят инженеров**: серьёзный бизнес требует людей с инженерным мышлением и глубоким пониманием технологий.
- **Другие области становятся инженерными**: HR, финансы, маркетинг.

### Инфраструктура данных для строительной компании

Руслан (строительная компания, 7-8 серверов с разнородными данными — PDF, сметы, чертежи, фотографии):
- Начинать не с архитектуры, а с процессов.
- Автоматизировать повторяющиеся задачи, считать экономику на уровне прототипов.
- Не пытаться одним решением перекрыть всё — делать маленькими шагами.

### Уровни доступа для компании (30 человек)

Алекс спросил о разграничении доступа к транскриптам и данным:
- По умолчанию все данные персональные.
- **Проекты** как единица доступа: у проекта есть метаданные, участники, каталог файлов.
- Для командной работы — Git-репозитории с правами доступа.
- Приватные данные (1-on-1 звонки) никогда не попадают в публичное пространство автоматически.

### Выбор инструментов

Обсуждение Notion vs Obsidian vs файлы:
- **Markdown файлы** — неизменная основа, потому что LLM работает с текстом.
- **MCP меняет правила**: не нужно выкачивать данные из Notion/Gmail — можно работать напрямую.
- **Linear** как источник правды для задач — можно быстро создать кастомные view (контент-календарь).

### Поиск дизрапта и стратегия стартапов

Глубокое обсуждение о том, как находить прорывные идеи:
- **Эффективный рынок**: если информация доступна всем, конкурентного преимущества нет.
- **Deep Research не даёт альфу**: он работает с общедоступной информацией.
- **Источники альфы**: приватные беседы с умными людьми, уникальные убеждения, bruteforce-тестирование (Gradient Descent для бизнеса).
- **Структура успешной компании**: визионер (живёт на 20 лет вперёд) + операционный партнёр (приземляет на процессы и KPI).
- **KPI research-организации**: количество экспериментов и итераций, не выручка.
